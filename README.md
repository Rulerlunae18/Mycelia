# Mycelia

Веб-редактор інтелект-карт: ідеї ростуть від кореневої думки гілками, як грибниця.
Курсова робота з дисципліни «Технології розроблення програмного забезпечення».

**Стек:** Vue 3 + Pinia + Vue Router (клієнт), Node.js + Express (сервер), Prisma ORM,
MySQL у розробці → PostgreSQL (Supabase) у продакшені, JWT в httpOnly-cookie.

## Структура

```
mycelia/
├── client/                    Vue 3 + Vite
│   └── src/
│       ├── core/              ядро предметної області БЕЗ Vue (патерни живуть тут)
│       │   ├── TreeNode.js    Composite
│       │   ├── layout/        Strategy: radial, tree, bilateral + LayoutContext
│       │   ├── render/        Bridge: MapRenderer + RenderBackend (SvgSceneBackend)
│       │   ├── theme/         Abstract Factory: ThemeFactory + теми forest, paper, ocean
│       │   ├── marks.js       каталог значків категорій і терміновості
│       │   ├── geometry.js    криві між вузлами
│       │   └── viewport.js    зум, панорама, «вписати»
│       ├── api/               fetch-обгортка (cookie, обробка помилок)
│       ├── stores/            Pinia: авторизація, редактор карти (вузли, виділення, розкладка), вкладки карт
│       ├── router/            маршрути і guard для сторінок
│       ├── views/             Login, Register, Maps, Editor
│       └── components/        AuthForm, NodeItem, MapCanvas (SVG-полотно)
└── server/                    Express + Prisma
    ├── prisma/schema.prisma   модель даних
    ├── src/
    │   ├── services/          шар SOA: AuthService, MapService (пізніше FileService, ExportService)
    │   ├── repositories/      єдине місце, що знає про Prisma
    │   ├── routes/            HTTP-маршрути (тонкі, без логіки)
    │   ├── middleware/        авторизація, обробка помилок
    │   ├── app.js             фабрика застосунку (залежності передаються ззовні)
    │   └── server.js          точка складання: Prisma → репозиторії → сервіси → HTTP
    └── tests/                 тести через фейкові репозиторії, без БД
```

Ланцюжок викликів: **route → service → repository → Prisma**. Сервіси нічого не знають
про Express і Prisma, тому їх можна тестувати без БД, а перехід MySQL → PostgreSQL
торкається тільки `schema.prisma`.

## Запуск

Потрібно: Node.js 20+, MySQL.

```bash
# 1. База даних
mysql -u root -p -e "CREATE DATABASE mycelia CHARACTER SET utf8mb4;"

# 2. Налаштування сервера
cp server/.env.example server/.env      # впиши DATABASE_URL і JWT_SECRET

# 3. Залежності (в корені; тут же згенерується клієнт Prisma)
npm install

# 4. Таблиці
cd server && npx prisma migrate dev --name init && cd ..

# 5. Два термінали
npm run dev:server      # http://localhost:3000
npm run dev:client      # http://localhost:5173
```

Тести: `npm test` (сервер і клієнт). Вони не потребують БД.

## API

| Метод | Шлях | Опис |
| --- | --- | --- |
| POST | `/api/auth/register` | `{ email, password }` → створює акаунт і ставить cookie |
| POST | `/api/auth/login` | `{ email, password }` → ставить cookie |
| POST | `/api/auth/logout` | очищає cookie |
| GET | `/api/auth/me` | поточний користувач |
| GET | `/api/maps` | список карт користувача |
| POST | `/api/maps` | `{ title, theme?, layout?, template? }` → карта з кореневим вузлом (з `template` ще й гілки зі зразка) |
| GET | `/api/maps/:id` | карта з вузлами, вкладеннями й областями |
| PATCH | `/api/maps/:id` | зміна назви, теми (forest / paper / ocean), розкладки |
| DELETE | `/api/maps/:id` | видалення |
| POST | `/api/maps/:id/nodes` | `{ parentId, text?, index? }` → новий вузол (index — позиція серед сусідів) |
| PATCH | `/api/maps/:id/nodes/:nodeId` | `text`, `collapsed`, `style`, `category` (idea / task / question / info / risk / decision або null), `priority` (low / normal / high / urgent або null), `note` (довга нотатка до 10000 символів, порожня = null) |
| POST | `/api/maps/:id/nodes/:nodeId/move` | `{ parentId, index? }` → список змінених позицій `{ id, parentId, order }` |
| GET | `/api/templates` | список шаблонів карт: `{ key, title, description, nodes }` |
| POST | `/api/maps/:id/nodes/restore` | відновлення гілки з тими самими id і позицією (для «Скасувати») → `{ nodes, changes }` |
| POST | `/api/maps/:id/nodes/:nodeId/duplicate` | копія гілки з усіма вкладеними одразу після оригіналу → `{ nodes, changes }` |
| POST | `/api/maps/:id/nodes/:nodeId/attachments?name=&mime=` | тіло: сирі байти файлу (до 25 МБ, до 10 на вузол, до 100 на карту) → опис вкладення |
| GET | `/api/maps/:id/attachments/:aid/file` | сам файл (картинки й відео inline, підтримується Range; решта лише для завантаження) |
| DELETE | `/api/maps/:id/attachments/:aid` | видаляє вкладення і файл |
| POST | `/api/maps/:id/boundaries` | `{ label?, nodeIds[] }` → пунктирна область навколо групи вузлів (до 50 на карту) |
| PATCH | `/api/maps/:id/boundaries/:bid` | `label`, `nodeIds` |
| DELETE | `/api/maps/:id/boundaries/:bid` | видаляє область |
| POST | `/api/maps/:id/links` | `{ fromId, toId, label? }` → зв'язок-стрілка між двома вузлами карти (не сам на себе, один на напрямок, до 500 на карту) |
| PATCH | `/api/maps/:id/links/:lid` | `label` (порожній підпис стає `null`) |
| DELETE | `/api/maps/:id/links/:lid` | видаляє зв'язок; зв'язки видаленого вузла зникають каскадом |
| DELETE | `/api/maps/:id/nodes/:nodeId` | видаляє вузол з піддеревом, повертає `{ deleted, changes }` |

Корінь карти не можна видалити чи перемістити; вузол не можна перемістити у власне піддерево;
на карті не більше 2000 вузлів.

Чужа карта повертає 404, а не 403, щоб не розкривати чужі id.

## Відомі обмеження

- MySQL обмежує вкладеність каскадних видалень самопосилання 15 рівнями. Видалення вузла це
  враховує (`NodeRepository.deleteLeafFirst`), але видалення цілої карти з гілкою глибшою за 15
  рівнів на MySQL може не пройти. У PostgreSQL такого обмеження немає.

## Безпека (що вже закладено)

- Паролі: bcrypt, 8–72 символи (межа bcrypt).
- JWT (HS256) в httpOnly-cookie: недоступний JavaScript, тому XSS його не вкраде.
  Заголовок `Authorization: Bearer` теж підтримується (Postman, тести).
- Однакова відповідь на неправильний email і неправильний пароль, щоб не розкривати, хто зареєстрований.
- Rate limit на `/api/auth`: 20 спроб за 15 хвилин з одного IP.
- `helmet`, CORS лише для `CLIENT_ORIGIN`, ліміт тіла запиту 1 МБ, валідація всіх входів через zod.

## Перехід на PostgreSQL (Supabase)

1. У `server/prisma/schema.prisma` змінити `provider = "mysql"` на `"postgresql"`.
2. У `.env` поставити рядок підключення Supabase.
3. Видалити `server/prisma/migrations` і створити заново: `npx prisma migrate dev --name init`.

Код сервісів і репозиторіїв не змінюється.

## Деплой (Render)

Клієнт і API на різних доменах, тому на сервері: `NODE_ENV=production`, `COOKIE_SAMESITE=none`,
`CLIENT_ORIGIN=<адреса клієнта>`; на клієнті: `VITE_API_URL=<адреса API>/api`.
Команда збірки сервера: `npm install && npx prisma migrate deploy`.

| Bridge (2-й бекенд) | `client/src/core/render/SvgFileBackend.js`: той самий `MapRenderer` малює у самодостатній SVG-файл, з якого `core/export.js` робить PNG (готово) |
| Command | `client/src/core/history.js`: `History` (invoker зі стеками скасування/повтору) і команди в `stores/mapEditor.js` (додати, видалити, перемістити, дублювати, перейменувати, згорнути) з `do`/`undo`/`redo` (готово) |
| Abstract Factory | `client/src/core/theme/`: `ThemeFactory` створює узгоджену родину продуктів (стиль вузла, лінії, значка, полотна); конкретні фабрики Ліс, Папір, Океан (готово) |

## Розкладки

Нова карта за замовчуванням двостороння (`bilateral`): це класичний вигляд карти думок, і вона
найкраще читається. `radial` компактна лише на малих картах: довгі підписи розсувають кільця, на
великих картах вона розповзається; `tree` росте вниз. Усі три не допускають перетину вузлів
(перевіряється тестами до 24 дітей кореня), 2000 вузлів рахуються за 5–40 мс.

Керування полотном: колесо миші масштабує навколо курсора, перетягування фону панорамує,
клік вибирає вузол, подвійний клік згортає або розгортає гілку, Enter на вузлі в фокусі вибирає його.

Перетягування вузла: кинь на середину іншого вузла, щоб зробити його дитиною (останньою), або на верхній чи нижній край (у «дереві» лівий чи правий), щоб стати сусідом до або після. Корінь не тягнеться, у власне піддерево кинути не можна. Логіка цілі скидання: `core/dragdrop.js` (чиста функція з тестами).

Гарячі клавіші (полотно має фокус після кліку по вузлу): `Tab` додає дитину, `Enter` сусіда після вузла, `F2` змінює текст, `Delete` видаляє (з підтвердженням), `Esc` знімає виділення. Новий вузол одразу відкривається для правки; під час правки `Enter` зберігає, `Esc` скасовує.

## Значки і теми

Категорії (ідея, задача, питання, інформація, ризик, рішення) малюються кружком із символом
зліва від тексту й розширюють вузол; терміновість (низька, звичайна, висока, термінова)
кружком на верхньому куті. Вибір у панелі над картою, коли вузол вибрано. Тема карти
зберігається в `maps.theme`; теми різняться лише виглядом, розкладка та сама. Тест перевіряє
контраст тексту (≥ 4.5) на вузлах і значках у кожній темі.

## Вкладки карт

Над редактором вкладки відкритих карт: клік перемикає, `✕` або середня кнопка миші закриває,
`＋` веде до списку карт, подвійний клік по назві активної вкладки перейменовує карту.
Вкладки зберігаються в `localStorage` окремо для кожного користувача (не більше 12, найстаріші
закриваються), а активною є карта з адреси `/maps/:id`. Закриття вкладки відкриває сусідню
праворуч, інакше ліворуч, інакше список. Вкладка видаленої карти закривається сама.
Запізніла відповідь сервера про карту, яку вже залишили, ігнорується.

## Області

Кнопка «▢ Обвести гілку» (коли вузол вибрано) створює пунктирну область навколо вузла і всієї
його гілки; назву й видалення можна змінити в панелі «Області» під картою. Область це підпис і
набір id вузлів, а малює її клієнт: опукла оболонка вузлів із відступом і скругленням
(`core/boundary.js`), колір дає фабрика теми. Згорнута гілка просто не впливає на контур,
видалений вузол сам зникає з області, а порожня область видаляється. Склад області не
змінюється, коли вузли переносять: вона описує групу, а не місце на полотні.

## Нотатки до вузлів

До вузла можна прикріпити довгий текст (до 10000 символів), якщо ідея не влазить у саму комірку.
Панель «Нотатка» з'являється під полотном для вибраного вузла і зберігає текст сама: через
1,2 с після друку, при виході з поля і при зміні вузла. На вузлі з нотаткою є значок сторінки.
Нотатка входить у історію (Ctrl+Z): правки одного вузла протягом 10 с зливаються в один крок.
Вона копіюється разом із гілкою (дублювання, шаблони) і відновлюється при скасуванні видалення.
Потрібна міграція БД: `npm run prisma:migrate -w server` (додає колонку `Node.note`).

## Вкладення

Вибери вузол: під картою з'являється панель вкладень. Файли додаються кнопкою або перетягуванням,
картинки показуються мініатюрами, відео програється прямо в панелі (`<video controls>`, Range),
решта файлів завантажується. На вузлі з вкладеннями видно скріпку з кількістю.

Безпека (файл користувача не має виконувати код у нашому домені):
- тип визначається за першими байтами файлу, а не за заявленим браузером: лише PNG, JPEG, GIF, WebP,
  MP4 і WebM вважаються картинкою чи відео; SVG, HTML та все інше стає звичайним файлом;
- звичайний файл віддається як `application/octet-stream` з `Content-Disposition: attachment`;
- усі файли йдуть із `Content-Security-Policy: sandbox` і `nosniff`, ім'я очищається від шляху;
- ключ у сховищі `mapId/uuid` не містить імені від користувача, і формат ключа перевіряється;
- чужа карта чи вкладення дають 404; видалення вузла, вкладення чи карти стирає й файл.

Файли зараз лежать у `server/uploads` (папка в `.gitignore`, змінюється через `UPLOAD_DIR`).
Це Strategy: `AttachmentService` знає лише інтерфейс `put / size / read / remove`
(`server/src/storage/`), тож перехід на Supabase Storage означає ще один клас того ж інтерфейсу.
На Render диск тимчасовий, тому до деплою сховище треба перенести (див. «Деплой»).

## Prototype: дублювання і шаблони

«⧉ Дублювати гілку» (вибраний вузол, не корінь) створює копію вузла з усіма вкладеними одразу після
нього, з приміткою «(копія)». Вкладення й області не копіюються, щоб не розмножувати файли.
При створенні карти можна вибрати шаблон: проєкт, SWOT, мозковий штурм, план тижня, курсова.
Усе це одна механіка: `NodePrototype` вміє `clone()` (глибока копія, нові id при записі), тому зразок
шаблону ніхто не псує, а дві карти з одного шаблону повністю незалежні. Шаблони зараз вбудовані в
код (`server/src/domain/templates.js`); таблиця `Template` у схемі лишилась для можливих
користувацьких шаблонів, але поки не використовується.

## Скасування і повтор (Command)

Кнопки ↶ ↷ у шапці, Ctrl+Z, Ctrl+Shift+Z / Ctrl+Y (за фізичною клавішею, тож працює й в українській розкладці).
Кожна дія редактора — об'єкт-команда з `do`/`undo`; `History` лише тримає стеки й нічого не знає про
вузли. Видалення відновлюється через `POST /nodes/restore` з тими самими id, тому позиція й виділення
збігаються. Новий вузол і його перша назва зливаються в один крок.
Обмеження: вкладення й належність до областей при скасуванні видалення не відновлюються; історія
скидається при завантаженні карти, перемиканні вкладки й перезавантаженні; розкладка, тема, області
та вкладення не скасовуються.

## Вигляд: екран входу і повний екран

На екранах входу й реєстрації фоном іде процедурна грибниця (`core/mycelium.js` вирощує мережу ниток
з країв екрана, `MyceliumBackdrop.vue` малює її на canvas), а світлові імпульси біжать від коренів до
кінчиків. При `prefers-reduced-motion` лишається статична картинка.
Над формою стоїть назва Mycelia (шрифт Fraunces) і випадкова думка з `core/quotes.js` (Cormorant); шапка на цих екранах прихована (`meta.bare` у маршрутах). Шрифти підключені пакетами `@fontsource`, тож працюють без зовнішніх запитів.
Кнопка «⛶ На весь екран» або клавіша `F` розгортає саме полотно карти (Fullscreen API); карта
автоматично вписується в новий розмір, `Esc` виходить.

## Вигляд вікна карти

Редактор у тій самій «грибній» мові, що екран входу і список карт: скляні панелі, вкладки з «бруньками»
(активна світиться), заголовок карти шрифтом Cormorant, два ряди керування (налаштування карти та дії
над вибраним вузлом), панелі «Нотатка» і «Вкладення» поруч, а «Області» й «Структура» як згортні
блоки. Спільні кольори й компоненти (`.card`, `.btn`, `select`, `kbd`) лежать у `client/src/style.css`.
Фон редактора тихіший за екран входу (`MyceliumBackdrop calm`), сторінка ширша за решту (`meta.wide`).

## Експорт карти

Кнопки «⤓ SVG», «⤓ PNG», «⤓ Markdown» в налаштуваннях карти. SVG збирає той самий `MapRenderer`, що малює полотно,
але з бекендом `SvgFileBackend` (Bridge): файл самодостатній, без CSS-змінних, у кольорах вибраної теми.
PNG це той самий SVG, намальований на canvas у двократному масштабі (з обмеженням 8192 пікселі за стороною).
Markdown зберігає структуру: корінь заголовком, гілки вкладеним списком, значки в дужках, нотатки цитатами.
У файл потрапляє те, що видно на екрані: згорнуті гілки лишаються згорнутими.

## Копіювання і вставка гілок

Ctrl+C копіює вибрану гілку в буфер (знімок `core/clipboard.js` без id), Ctrl+X вирізає (гілка видаляється, але лишається
в буфері, і це можна скасувати), Ctrl+V вставляє її дитиною вибраного вузла (без вибору в корінь) з новими id; ті самі
дії є кнопками «⎘ Копіювати» і «⎗ Вставити». Буфер живе поза картою, тому гілку можна скопіювати в одній вкладці і
вставити в іншій (поки сторінку не перезавантажено). Вставка йде існуючим `POST /nodes/restore`, тож сервер не змінювався;
вона входить у історію (Ctrl+Z). Нотатки, значки і стиль копіюються; вкладення й області ні. Системний буфер обміну
додатково отримує текстовий список гілки.

## Зв'язки між вузлами

Крім дерева, між будь-якими двома вузлами (навіть з різних гілок) можна провести стрілку з підписом, наприклад
«впливає на». Кнопка «↔ Зв'язати» або клавіша L на вибраному вузлі вмикає режим: клацни вузол-ціль (Esc скасовує).
Клік по стрілці виділяє її, і в панелі можна змінити підпис або видалити (Delete); усі зв'язки є ще й списком «Зв'язки».
Стрілки A→B і B→A згинаються в різні боки (`linkPath` у `core/geometry.js`), штрих і колір беруться з теми:
`LinkStyle` додано до родини продуктів Abstract Factory, а `drawLink` до контракту Bridge, тому SVG-експорт малює їх
без змін у рендерері; Markdown отримує розділ «Зв'язки». Згорнута гілка ховає свої зв'язки. Усе входить в історію
(Ctrl+Z); команди тримають зв'язок за парою вузлів, бо після скасування видалення сервер видає новий id.
Нова таблиця `Link`: після оновлення виконай `npm run prisma:migrate -w server`. Копіювання гілки зв'язки не переносить.

## Палітра

Усі кольори інтерфейсу зібрані в одному блоці «ПАЛІТРА» на початку `client/src/style.css` (фон, скло карток, текст,
акцент-світіння, кольори ниток і імпульсів грибниці). Щоб підкрутити, змінюй лише його: компоненти беруть кольори зі змінних,
а canvas-фон грибниці читає ті самі змінні (`core/palette.js`). Значення з `-rgb` це три числа через пробіл (`179 162 238`),
з ними працюють прозорості. Нова палітра «Ягоди» (лавандове світіння на зеленувато-чорному тлі) стала типовою;
попередня лісова лишилась як `:root[data-palette='forest']`, щоб порівняти: у консолі браузера
`document.documentElement.dataset.palette = 'forest'`. Тема полотна карти окрема (Abstract Factory), для неї додано
фабрику «Ягоди» (типова для нових карт; старі карти зберігають свою тему). Тест `palette-css.test.js` стежить, щоб кожна
змінна кольору мала значення в обох палітрах.
